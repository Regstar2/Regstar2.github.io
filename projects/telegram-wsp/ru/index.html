Telegram-WSP

Telegram для Android со встроенным непосредственно в клиент TgWsProxy.

Проект сохраняет Telegram максимально близким к upstream: TgWsProxy работает за локальным прокси, tgnet не изменяется, а интеграция применяется как небольшой воспроизводимый overlay.

> подход

Минимальные изменения оригинального Telegram

Интеграция намеренно не заменяет сетевую подсистему Telegram. Текущий source-level overlay затрагивает только пять upstream-файлов и не изменяет TMessagesProj/jni/tgnet/.

01 / интеграция

Прокси за штатным Telegram proxy API

Telegram-WSP запускает tgwsproxy-core локально и настраивает 127.0.0.1:1443 через обычный proxy API Telegram. Самому Telegram не нужно знать, как реализован внешний WebSocket transport.

02 / брендинг

НЕОФИЦИАЛЬНЫЙ ФОРК

Собственные название, иконка, package и ключ подписи.

Опубликованные требования Telegram просят сторонние приложения не использовать стандартный логотип Telegram и не выдавать себя за официальный клиент. Поэтому Telegram-WSP использует собственный брендинг и явно обозначен как неофициальный.

> реализовано

Основные возможности

Текущий MVP сосредоточен на встроенном proxy path, воспроизводимом переносе новых версий Telegram, целостности релизов и низкой стоимости поддержки форка.

01WSP

Встроенный TgWsProxy

Для обычного сценария Telegram-WSP отдельное приложение прокси не требуется.

02LOCAL

Локальный MTProto listener

Runtime слушает 127.0.0.1:1443 и подключается через существующий proxy API Telegram.

03DIFF

Небольшой upstream diff

Overlay намеренно ограничен, чтобы уменьшить число конфликтов при выходе новых версий Telegram Android.

04REL

Автоматизированные подписанные релизы

GitHub Actions собирает полный APK, подписывает постоянным ключом проекта и публикует metadata и Corresponding Source.

05UPD

Проверяемые обновления приложения

Клиент проверяет GitHub Releases и валидирует SHA-256, package ID и сертификат подписи перед передачей APK Android.

06SYNC

Синхронизация Telegram upstream

Плановый workflow ежедневно проверяет DrKLO/Telegram и выпускает новую WSP-сборку только после успешных overlay и CI gates.

> автоматизация

Обновления Telegram автоматически превращаются в WSP-релизы

Pipeline разделяет обнаружение новой upstream-версии и пользовательский релиз: несовместимая версия Telegram не становится Telegram-WSP-релизом только потому, что появилась upstream.

ПРОВЕРЯЕМОЕ ОБНОВЛЕНИЕ

Установленное приложение следует за релизами Telegram-WSP.

Updater читает latest.json, проверяет более высокий versionCode, скачивает APK и валидирует digest, package ID и сертификат подписи. Финальное подтверждение установки остаётся за пользователем и Android.
