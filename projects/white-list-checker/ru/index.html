> android / диагностика мобильной сети

WhiteListChecker

Диагностика доступности мобильной сети и обнаружение наблюдаемых признаков режима белых списков.

WhiteListChecker выполняет проверки через явно полученный cellular Network, даже если Wi-Fi остаётся основной сетью телефона. Приложение объединяет HTTPS-проверки с DNS-диагностикой, хранит результаты локально и отслеживает изменения во времени.

$ контекст

Что измеряет приложение

WhiteListChecker не имеет доступа к внутренним правилам фильтрации оператора. Приложение показывает наблюдаемое сетевое поведение и намеренно не выдаёт результат за доказательство конкретного механизма на стороне оператора.

01 / проблема

Один неудачный запрос не объясняет, почему ресурс недоступен.

Причиной могут быть маршрутизация, DNS, TLS, временная потеря связи, VPN или туннель, настройки устройства либо фильтрация на стороне сети. Одной проверки «работает / не работает» недостаточно для полезной диагностики.

02 / подход

Измерять прямой cellular-маршрут по нескольким независимым сигналам.

Приложение получает отдельный cellular Network, выполняет привязанные к нему HTTPS- и DNS-проверки, использует DNS как дополнительную диагностику, а затем локально сохраняет состояние для истории, статистики и мониторинга.

> возможности

Основные возможности

Стабильная версия сосредоточена на прямой диагностике cellular-сети и не требует аккаунта или backend-сервиса владельца проекта.

01
CELL

Явная cellular-маршрутизация

Использует ConnectivityManager.requestNetwork(...) для получения TRANSPORT_CELLULAR без глобального bindProcessToNetwork для всего процесса.

02
HTTPS

Проверки сайтов через выбранную сеть

Проверяет редактируемые группы LOCAL и FOREIGN через полученный cellular Network с обычной проверкой TLS-сертификата и имени хоста.

03
DNS

DNS-диагностика

Поддерживает редактируемые resolver, UDP/53, fallback на TCP/53 и разрешение имён через cellular. DNS остаётся дополнительным сигналом, а не единственным классификатором.

04
DATA

История и статистика

Room хранит историю проверок, результаты по целям, статистику и timeline состояний. Данные можно экспортировать в CSV, JSON или TXT.

05
MON

Фоновый и активный мониторинг

Периодические проверки выполняются через WorkManager, а явно запущенный непрерывный мониторинг работает через foreground service.

06
NTF

Уведомления

Поддерживает локальные Android-уведомления и опциональный личный Telegram через Cloudflare Worker и Telegram-бота пользователя.

07
UPD

Проверка обновлений

Checks official GitHub Релизs asynchronously, filters stable/prerelease versions and lets the user open the official release page.

08
ISSUE

Встроенная обратная связь

Действия для bug report и feature request открывают GitHub Issue Forms без встраивания GitHub PAT или OAuth write credential в APK.

09
I18N

Русский и английский интерфейс

Пользовательские диалоги, уведомления, accessibility-описания и ошибки локализованы через Android resources.

$ схема_сигналов

Как формируется результат

Доступность сайтов — основной сигнал классификации. DNS используется как дополнительный, поэтому один недоступный публичный resolver не превращается автоматически в общую DNS-ошибку мобильной сети.

Экраны приложения

Это актуальные скриншоты из репозитория проекта.

$ архитектура

Runtime-архитектура

Приложение использует MVVM, domain use cases и ручной composition root AppContainer. Логика checker, хранение данных и классификация не реализуются внутри Compose-компонентов.

UI

Jetpack Compose + Material 3, MainViewModel и AppUpdateViewModel.

Domain

WhitelistCheckUseCase, CheckAndNotifyUseCase, CheckForAppUpdateUseCase и WhitelistStateClassifier.

Network

CellularNetworkProvider, MobileSiteChecker, CellularDnsResolver и OkHttp с socket factory выбранного cellular Network там, где это требуется.

Persistence

Room schema 8 для истории, статистики и timeline; DataStore Preferences — для настроек приложения, checker, уведомлений и мониторинга.

Background

WorkManager для периодических проверок и ActiveMonitoringService для явно запущенного foreground-мониторинга.

Optional integrations

Public GitHub Релизs API for update discovery and a user-owned Cloudflare Worker for personal Telegram integration.

$ инженерные_решения

Инженерные решения

Эти ограничения являются частью дизайна продукта, а не отсутствующими функциями.

Изоляция cellular

Не привязывать весь процесс к мобильной сети

Checker получает отдельный cellular Network и создаёт через него DNS/HTTPS-трафик. Process-wide bindProcessToNetwork намеренно не используется.

Классификация

Не считать DNS всей диагностикой

Проверки сайтов являются основным сигналом. DNS остаётся дополнительным, поэтому сбои публичных resolver не создают вводящее в заблуждение общее состояние.

Достоверность измерения

Без proxy/VPN-транспорта внутри checker

Proxy или туннель меняет измеряемый путь. Поддержка такого транспорта внутри checker противоречила бы цели прямой cellular-диагностики.

Local-first миграция

Удалить старый центральный сервис без потери истории

Room schema 8 удаляет устаревшую таблицу pending_public_reports миграцией 7 → 8, сохраняя историю, статистику, цели и настройки.

Фоновое выполнение

Использовать подходящую модель фонового выполнения Android

WorkManager выполняет запланированную периодическую работу. Foreground Service используется только для активного мониторинга, явно запущенного пользователем.

Доставка обновлений

Проверять обновления без скрытой само установки

The app checks public GitHub Релизs, filters prereleases and opens the official release page. APK download and installation remain under user and Android control.

> приватность

LOCAL-FIRST

Для основной функциональности центральный сервис не требуется.

Начиная с v1.0.0 старый центральный/public service владельца проекта удалён. Проверки, история и статистика остаются на устройстве.

  • История проверок хранится локально
  • Статистика хранится локально
  • Обязательный аккаунт не нужен
  • Нет центрального backend владельца проекта для диагностики
  • Проверка обновлений не отправляет историю или настройки
  • Личный Telegram опционален и принадлежит пользователю

> безопасность

ГРАНИЦЫ БЕЗОПАСНОСТИ

Диагностика без ослабления транспортной безопасности.

HTTPS-проверки сохраняют обычную проверку TLS-сертификата и имени хоста. APK не содержит GitHub PAT/OAuth write token или Telegram BOT_TOKEN.

  • Проверка TLS-сертификата остаётся включённой
  • Проверка имени хоста остаётся включённой
  • Нет GitHub PAT/OAuth secret в APK
  • Нет Telegram BOT_TOKEN в APK
  • Релиз keystore and credentials stay outside Git
  • Feedback открывает публичные GitHub Issue Forms
